## NSIS 打包失败排查（14:20-14:58，同一天下午）

### 现象
```
Warn NSIS directory is missing some files. Recreating it.
Downloading .../nsis-3.zip            → 成功
Downloading .../NSIS-ApplicationID.zip → Connection Failed (os error 10060)
Error failed to bundle project
```
随后一次重试变成 `拒绝访问。(os error 5)`，且 Bash/PowerShell 直接跑均无输出、只有 exit 1。

### 根因（两个叠加，用户猜测"Tauri 2 项目冲突"方向是对的）
1. **Tauri 1 与 Tauri 2 共用同一 NSIS 缓存目录**：`C:\Users\dingd\AppData\Local\tauri\NSIS`
   - 用户另一个 Tauri 2 项目同时在 build → 抢锁
   - 日志佐证：`Blocking waiting for file lock on package cache` + `拒绝访问 (os error 5)`
   - 当时 `tasklist` 抓到 **cargo.exe + rustc.exe 正在运行**
2. **间歇性网络**：其实 `api.github.com` 直连 200（0.81s）、`github.com` 200，网络是通的；
   超时是偶发。Clash 未运行（ProxyEnable=0，7890 等端口全不通），镜像站（ghfast/ghproxy 等）也拿不到文件。

### 结论：不需要换 NSIS 版本，也不需要手动补缓存
占用解除（另一个项目 build 完）后，原样重跑即成功：
```
Downloading nsis-3.zip                 → Info extracting NSIS
Downloading NSIS-ApplicationID.zip     → Info extracting NSIS ApplicationID plugin
Downloading nsis_tauri_utils.dll       → Info validating hash
Finished 1 bundle
```
产物：exe `14:58:32`、installer `14:58:49`；缓存已完整（`NSIS/Plugins/x86-unicode/ApplicationID.dll` 就位）。

### 复用经验（下次遇到直接照做）
1. **先查占用**：`tasklist | grep -iE "^cargo|^rustc|makensis"`——有则等它结束，串行 build，别并行。
2. **输出落盘再读**：`npm run tauri build > build_log.txt 2>&1; tail -30 build_log.txt`
   直接 pipe 到 tail 在本环境会偶发"exit 1 且零输出"，落盘才能拿到真实错误。
3. **别急着换 target**：WiX 在 `tauri\WixTools314`（独立目录，不冲突）是备选；改 `tauri.conf.json`
   的 `bundle.targets` 为 `["msi", ...]` 可彻底绕开 NSIS，但本次没必要。
4. **网络判断**：先 `curl -s -o /dev/null -w "%{http_code}" https://api.github.com`，
   通就说明只是偶发超时/占用，重试即可，不必找镜像。

## 第十二轮 15:30：npm 镜像自动切换（采纳用户方案 A，已实施）

### 用户方案
"npm 支持单行命令内给镜像源的，你去试试，或者直接帮小白改文件，如果是官方源且是墙内环境（ping chatgpt.com 就知道了）"

### 先验证再动手（实测结论）
1. `--registry=<url>` 单行指定**有效**：`npm view @deepseek-ai/dsh version --registry=...`
   淘宝源与官方源均正确返回 `0.1.5-rc.2`
2. `chatgpt.com` 判定墙内**有效**：本机 `http=000` 6s 超时 → 判定国内
   （用 HTTP 而非 ICMP ping，因为 ping 常被防火墙丢弃）
3. 实测速度：官方 1.80/1.54/1.34s vs 淘宝 0.19/0.24/0.21s → **淘宝快 6-7 倍**

### 实现（改 6 文件，均先备份 `*.bak.20260919`/`b`/`c`）
**`dsh.rs`（末尾新增）**
- 常量 `NPM_OFFICIAL` / `NPM_MIRROR`
- `read_npm_registry()` / `write_npm_registry()`：执行 `npm config get|set registry`，
  调 `hide_console_cmd()` 隐藏黑窗（`creation_flags(0x08000000)`）
- `detect_in_china()`：reqwest 请求 `https://chatgpt.com`，**3 秒**超时，`is_err()` = 墙内
- 三个命令：`get_npm_registry`（只读）/ `ensure_npm_mirror`（按需切换）/ `set_npm_registry`（手动）
- 切换条件严格：`in_china && is_official` 才写 `~/.npmrc`，已配镜像或境外用户零影响
- `set_npm_registry` 只接受含 `npmjs.org` 或 `npmmirror` 的 URL，防注入

**`lib.rs`**：注册三个命令
**`tauri-api.ts`**：`NpmRegistryInfo` 接口 + 三个方法
**`App.ts`**：启动时 `void this.ensureNpmMirror()`（**后台执行，不 await**）
**`settings.html` / `main.ts`**：版本面板加「npm 源」下拉 + 「网络环境」文本，可手动切换

### 关键性能决策（重要）
- 网络检测超时 **5s → 3s**：这个检测在启动链路里，太长会明显拖慢启动
- `ensureNpmMirror()` **不 await**（fire-and-forget）：国内网络下最多等 3 秒，绝不能阻塞 `autoStart()`
- Rust 端切换/失败时 emit `service-log`；App.ts 成功时不再重复打日志，避免刷屏

### 构建验证（15:36 落地）
- `EXIT=0`，cargo 27.29s（先 taskkill 旧 app 避免 LNK1104）
- exe `15:36:42` / installer `15:36:50`
- 铁证：二进制命中「检测到国内网络且 npm 使用官方源」/`registry.npmmirror.com`/`chatgpt.com` 各 1；
  lib.rs 三个命令注册命中 3；dist/settings.html 命中 npm-registry-select + npm-network-text 共 2

### 可复用模式（其他项目照抄）
```
判定墙内: HTTP GET https://chatgpt.com，3s 超时，失败=国内
判定源:   npm config get registry（含 registry.npmjs.org = 官方源）
切换:     国内 && 官方源 → npm config set registry https://registry.npmmirror.com
单行指定: npm install <pkg> --registry=https://registry.npmmirror.com（临时生效，适合不改配置的场景）
```
注：改 `~/.npmrc` 影响用户全局（含 pnpm，因 pnpm 也读 .npmrc），对小白是净收益；

- publish 后目录里**散落 DLL 数量 = 0**，只有一个 exe → 单文件已成立，IExpress 是多余步骤
- `publish\DSsetup.SED`（IExpress 配置，8/19 生成，比产物还早）属**历史遗留**，
  里面列的一堆 `Aprillz.MewUI.*.dll` 现已全部打进单文件

### 80 MB 的真实构成
- .NET 8 **自包含运行时** ≈ 70 MB
- 内嵌的 Tauri 产物 `DeepseekHarness.exe` ≈ 10 MB（csproj 用 `EmbeddedResource` 嵌入）
→ 与 v1.2.0 release 资产的 80.24 MB 吻合

### 采用的瘦身方案（用户选「加单文件压缩」）
csproj 加一行：
```xml
<EnableCompressionInSingleFile>true</EnableCompressionInSingleFile>
```
同时 `<Version>1.2.1</Version>` → `1.3.0`（与其他四处同步）。

**结果：80.24 MB → 39.32 MB（减少 51%）**，仍是自包含（用户无需装 .NET），
代价是首次启动需解压到临时目录、慢约 0.5–1 秒。

### 构建命令（可复用）
```bash
dotnet publish setup/DeepseekHarness.Setup/DeepseekHarness.Setup.csproj -c Release -r win-x64
```
产物：`setup/DeepseekHarness.Setup/bin/Release/net8.0-windows/win-x64/publish/DeepseekHarness.Setup.exe`
- 前置条件：csproj 有 `CheckReleasePayload` target，构建前会校验 `src-tauri/target/release/DeepseekHarness.exe` 存在
  （即**必须先跑完 tauri build**）

### 未采用的方案（留档）
- `PublishTrimmed`：可再降到 25–30 MB，但 MewUI/Direct2D 与 Vanara PInvoke 用反射，有运行风险，需实测
- `SelfContained=false`：仅 ~12 MB，但用户必须自装 .NET 8，对小白不友好
